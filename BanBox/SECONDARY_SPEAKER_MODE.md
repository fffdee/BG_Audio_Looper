# 副音箱模式使用说明

## 概述

副音箱模式是一个简化的工作模式，专门为副音箱场景设计。在此模式下，设备仅执行简单的混音功能，将所有音频输入源混合后输出，不使用任何效果器和Looper功能。

## 功能特点

### 主音箱模式（默认模式）
- ✅ 完整的效果器链（EQ、混响、动态压缩等）
- ✅ Looper录音和播放功能
- ✅ 节拍器支持
- ✅ 所有高级音频处理功能
- ⚠️ 相对较高的CPU占用

### 副音箱模式
- ✅ 简单的音频混音
- ✅ 支持所有输入源（ADC0、ADC1、USB、蓝牙）
- ✅ 支持所有输出（DAC0、USB）
- ✅ 较低的CPU占用
- ❌ 无效果器处理
- ❌ 无Looper功能
- ❌ 无节拍器功能

## 使用方法

### 查看当前模式
```bash
mode
```

### 切换到副音箱模式
```bash
mode secondary
```

### 切换回主音箱模式
```bash
mode main
```

### 显示帮助信息
```bash
mode help
```

## 音频路由

### 主音箱模式音频链路
```
[ADC0 Guitar] ──┬─> [EQ L] ──┐
                └─> [EQ R] ──┤
                             ├─> [Mixer] ─> [Expander] ─> [DRC] ─> [Reverb] ─> [Final Mixer] ─> [DAC0/USB]
[ADC1 Mic]    ──┬─> [EQ L] ──┤                                                      ↑
                └─> [EQ R] ──┘                                                      │
[USB/BT]      ──> [Mixer] ─> [EQ] ──────────────────────────────────────────────────┘
[Looper Play] ─────────────────────────────────────────────────────────────────────┘
[Metronome]   ──> [USB_BT_Mixer] ───────────────────────────────────────────────────┘
```

### 副音箱模式音频链路
```
[ADC0]  ─┬─> [L] ─────┐
         └─> [R] ─────┤
[ADC1]  ─┬─> [L] ─────┤
         └─> [R] ─────┤
[USB_IN] ─────────────┼─> [Mixer] ─> [DAC0/USB]
[BT_IN]  ─────────────┘
```

## 重要说明

1. **设置不保存到Flash**
   - 模式切换是临时的，不会保存到Flash存储器
   - 设备断电重启后会自动恢复到主音箱模式
   - 这是设计行为，确保默认状态下始终有完整功能

2. **自动停止Looper**
   - 切换到副音箱模式时，系统会自动停止所有Looper段的录制和播放
   - 已录制的数据保留在Flash中，切换回主音箱模式后可以继续使用

3. **效果图预设**
   - 主音箱模式使用 `GRAPH_PRESET_DEFAULT` 预设（21个节点的完整配置）
   - 副音箱模式使用 `GRAPH_PRESET_SECONDARY_SPEAKER` 预设（7个节点的简化配置）

4. **性能提升**
   - 副音箱模式下，由于移除了所有效果器处理，CPU占用显著降低
   - 适合作为被动扩音设备使用，延迟更低

## 应用场景

### 适合副音箱模式的场景
- 🎵 作为主音箱的扩音设备
- 🎵 需要低延迟的简单音频延伸
- 🎵 多房间音频分发
- 🎵 不需要音频处理的播放场景

### 适合主音箱模式的场景
- 🎸 现场演奏需要效果器
- 🎤 录音和循环演奏（Looper功能）
- 🎶 需要音频处理和优化
- 🥁 需要节拍器辅助

## 技术细节

### 预设配置对比

| 项目 | 主音箱模式 | 副音箱模式 |
|------|-----------|-----------|
| 节点数量 | 21个 | 7个 |
| 连接边数 | 22条 | 8条 |
| 内存占用 | 较高 | 较低 |
| CPU占用 | 较高 | 较低 |
| 延迟 | 正常 | 较低 |

### 实现原理
- 使用Effect Graph系统的预设配置机制
- 动态切换不同的音频处理图（Graph）
- 通过`EffectGraphConfig_LoadPreset()`函数加载不同预设
- 避免了运行时的条件判断开销
