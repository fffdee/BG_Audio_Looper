# BanGTsynth SD卡+NAND+PSRAM 合成器实现方案

## 方案概述

### 目标
实现一个新的合成器驱动方案，利用 SD卡、NAND Flash 和 PSRAM 的协同工作，提高合成器运行效率。

### 核心架构
```
SD卡 (FAT32) → NAND Flash → PSRAM → 音频输出
   ↓              ↓            ↓
音源加载      音色缓存     音符缓冲
```

### 工作流程
1. **SD卡读取**: 开机时从 SD卡读取 SF2 音源文件 (FAT32 文件系统)
2. **NAND存储**: 将音源数据按 MIDI 程序号存储到 NAND Flash
3. **PSRAM缓存**: 播放时将音符数据加载到 PSRAM 音符缓冲区
4. **实时合成**: 按采样率从 PSRAM 读取数据进行音频合成

### 优势
- **存储层次化**: SD卡(大容量) → NAND(中速缓存) → PSRAM(高速缓冲)
- **内存优化**: 避免大块音源数据常驻内存
- **加载效率**: MIDI 程序预加载，音符按需加载
- **并发性能**: 多音符同时播放时减少存储访问冲突

## 实现步骤

### Step 1: FAT32 最小读取器
实现 SD卡 FAT32 文件系统的基本读取功能，支持 SF2 文件定位和读取。

#### 1.1 FAT32 引导扇区解析
- 解析 MBR 分区表
- 读取 FAT32 引导扇区 (BPB)
- 提取关键参数: 扇区大小、簇大小、FAT表位置、根目录位置

#### 1.2 目录遍历
- 实现目录项解析 (32字节结构)
- 支持长文件名 (LFN) 解析
- 实现递归目录遍历，查找 .sf2 文件

#### 1.3 文件读取
- 实现簇链读取 (FAT表解析)
- 支持大文件读取 (SF2文件可能 > 100MB)
- 实现文件偏移读取 (用于音源数据定位)

#### 1.4 SD卡接口适配
- 基于现有 sd_card_driver.c 封装
- 实现扇区级读写接口
- 添加 FAT32 错误处理和重试机制

### Step 2: NAND 音色布局定义与存储接口
定义 NAND Flash 中的音色数据布局，实现音色数据的存储和检索。

#### 2.1 NAND 存储布局设计
```
NAND Flash 布局 (256MB):
+-------------------+
| 系统保留区        | 0MB - 32MB
+-------------------+
| 音色索引表        | 32MB - 64MB
+-------------------+
| 音色数据区        | 64MB - 256MB
+-------------------+
```

#### 2.2 音色索引表结构
- 程序号映射表 (MIDI Program → NAND 偏移)
- 音色元数据 (名称、大小、校验和)
- 坏块管理表 (NAND 坏块标记)

#### 2.3 NAND 存储接口
- 基于现有 flash_nand_w25n02.c 封装
- 实现音色数据写入/读取
- 添加 ECC 校验和坏块管理
- 实现磨损均衡 (wear leveling)

#### 2.4 MIDI 程序映射
- 实现 MIDI Program Change 到 NAND 偏移的映射
- 支持音色切换时的快速定位
- 缓存最近使用的音色索引

### Step 3: PSRAM 音符缓冲区管理
实现 PSRAM 中的音符数据缓存机制，支持多音符并发播放。

#### 3.1 PSRAM 内存布局
```
PSRAM 布局 (8MB):
+-------------------+
| 音符缓冲区池      | 0MB - 6MB (96个缓冲区 x 64KB)
+-------------------+
| 缓冲区管理表      | 6MB - 8MB
+-------------------+
```

#### 3.2 缓冲区管理
- 音符缓冲区分配/释放 (64KB per note)
- LRU 缓存替换策略
- 并发访问保护 (FreeRTOS mutex)

#### 3.3 音符数据加载
- 从 NAND 异步加载音符数据到 PSRAM
- DMA 加速数据传输
- 预加载机制 (预测下一个音符)

#### 3.4 音频合成接口
- PSRAM 到音频缓冲区的实时拷贝
- 插值处理 (不同采样率转换)
- 音符释放时的缓冲区清理

### Step 4: 合成器核心集成
将新的存储层次集成到现有的合成器框架中。

#### 4.1 存储层抽象
- 扩展 bg_storage.h 接口
- 支持多级存储 (SD → NAND → PSRAM)
- 统一的读写接口

#### 4.2 SF2 解析器适配
- 修改 sf2_parser.c 支持新存储接口
- 实现音符数据的按需加载
- 优化内存使用 (减少常驻数据)

#### 4.3 MIDI 控制器集成
- Program Change 时切换 NAND 音色
- Note On 时分配 PSRAM 缓冲区
- Note Off 时释放缓冲区

#### 4.4 性能优化
- DMA 传输优化
- 缓存预取策略
- 内存对齐优化

### Step 5: 系统集成与测试
将新方案集成到 BanBox 系统并进行全面测试。

#### 5.1 宏隔离实现
- 在 product_def.h 中添加 `SYNTH_SD_NAND_PSRAM_EN`
- 条件编译隔离新旧方案
- 保持向后兼容性

#### 5.2 启动流程集成
- 开机 SD卡检测和 FAT32 挂载
- NAND 音色数据初始化
- PSRAM 缓冲区池初始化

#### 5.3 错误处理
- SD卡未插入时的降级处理
- NAND 坏块检测和修复
- PSRAM 访问失败时的恢复

#### 5.4 性能测试
- 音符触发延迟测试
- 多复音并发性能测试
- 内存使用统计
- CPU 使用率监控

## 依赖关系

### 硬件依赖
- SD卡插槽 (GPIO_A15/A16/A17)
- NAND Flash (GPIO_A29)
- PSRAM (GPIO_B6)

### 软件依赖
- sd_card_driver.c/h
- flash_nand_w25n02.c/h
- psram_esp64h.c/h
- FreeRTOS (任务调度、互斥锁)
- DMA 驱动 (数据传输加速)

### 内存需求
- RAM: +2KB (FAT32 缓存) +4KB (NAND 索引缓存)
- PSRAM: 6MB (音符缓冲区)
- NAND: 192MB (音色数据存储)

## 风险评估

### 技术风险
1. **FAT32 复杂性**: FAT32 协议相对复杂，实现最小读取器需要仔细处理边界情况
2. **NAND 可靠性**: NAND Flash 有坏块和磨损问题，需要完善的 BBM 和 wear leveling
3. **实时性能**: 多级存储访问可能引入延迟，需要优化 DMA 和缓存策略

### 缓解措施
1. **分阶段实现**: 先实现基础功能，再逐步优化性能
2. **降级策略**: SD卡/NAND 访问失败时自动降级到原有方案
3. **测试覆盖**: 编写全面的单元测试和集成测试
