# 第3章：设备驱动层 (02_device_drivers)

> **本章目标**：理解各硬件外设的设备驱动实现
> **对应代码**：`BanBox/src/banux/02_device_drivers/`

---

## 3.1 设备驱动层概述

设备驱动层位于 HAL 之上，实现各外设的**完整驱动程序**，包括初始化、状态管理、数据收发等功能。每个驱动模块独立管理一个硬件子系统。

### 模块清单 (7个子系统)

```
02_device_drivers/
├── bluetooth/        # 蓝牙双模协议栈 (Classic BT + BLE)
├── flash/            # Flash 存储管理 (NOR + NAND + PSRAM + SD)
├── lcd/              # ST7735 LCD 显示驱动
├── power_mgr/        # 电源/电池管理
├── remind_sound/     # 提示音播放 (MP3/WAV 解码)
├── sdcard/           # SD 卡文件系统
└── USB/              # USB Device (CDC + Audio)
```

## 3.2 蓝牙子系统 (bluetooth/)

> **最复杂的驱动模块**，包含经典蓝牙和低功耗蓝牙两套协议栈

### 3.2.1 模块结构

```
bluetooth/
├── inc/                       # 头文件
│   ├── bt_manager.h           # 蓝牙管理器（核心状态机）
│   ├── bt_vfs_driver.h        # 蓝牙 VFS 驱动适配
│   ├── ble_protocol.h         # BLE 应用层协议
│   ├── ble_api.h              # BLE 底层 API
│   ├── ble_app_callback.h     # BLE 事件回调
│   ├── ble_process.h          # BLE 旧协议解析器
│   ├── shell_io_ble.h         # Shell over BLE

└── src/                       # 源文件 (实现)
```

### 3.2.2 蓝牙管理器 (`bt_manager`)

蓝牙管理器是整个蓝牙子系统的 **状态中枢**，维护着所有蓝牙状态机。

**核心状态机**：

| 状态机 | 状态数 | 说明 |
|--------|--------|------|
| `BT_STACK_STATE` | 3 | NONE → INITIALIZING → READY |
| `BT_SCAN_PAGE_STATE` | 6 | 扫描/配对/断开等 |
| `BT_HFP_STATE` | 7 | 免提通话状态 (NONE → 3WAY_ACTIVE) |
| `BT_A2DP_STATE` | 5 | 音频流状态 (NONE → STREAMING) |
| `BT_AVRCP_STATE` | 3 | 媒体控制状态 |
| `BT_SPP_STATE` | 3 | 串口透传状态 |

**核心数据结构**：

```c
typedef struct {
    uint8_t  local_name[32];        // 本机蓝牙名称
    uint8_t  local_mac[6];          // 本机 MAC 地址
    uint8_t  remote_mac[6];         // 远端设备 MAC
    uint8_t  conn_mode;             // 连接模式
    // ... HFP/A2DP/AVRCP/SPP 各状态
    uint8_t  sco_state;             // SCO 音频链路状态
    uint8_t  caller_number[20];     // 来电号码
    uint8_t  battery_level;         // 电池电量（HFP 上报）
    int8_t   rssi;                  // 信号强度
} BT_MANAGER_ST;
```

**关键 API**：

```c
BT_MANAGER_ST* GetBtManager(void);       // 获取全局单例
void SetBtStackState(uint8_t state);      // 设置协议栈状态
void BtHfpConnect(void);                 // 连接 HFP
void BtA2dpConnect(void);               // 连接 A2DP
void BtAvrcpConnect(void);              // 连接 AVRCP
void BtSppConnect(void);                // 连接 SPP
void BtReconnectDevice(void);           // 回连上次设备
```

### 3.2.3 BLE 协议层 (`ble_protocol`)

定义 MCU 与手机 App 之间的 **二进制帧协议**，支持可靠传输。

**帧格式**：

```
┌──────┬──────┬─────┬─────┬──────┬──────────┬──────┐
│0xAA  │0x55  │ CMD │ SEQ │ LEN  │ PAYLOAD  │CRC16 │
│HEAD0 │HEAD1 │1byte│1byte│1byte │ 0-247byte│2byte │
└──────┴──────┴─────┴─────┴──────┴──────────┴──────┘
```

**命令集** (`BleProtoCmd_t`)：

| 组 | 命令 | 值 | 用途 |
|----|------|-----|------|
| 控制 | `ACK` | 0x00 | 确认收到 |
| 控制 | `NACK` | 0x01 | 否认（重传） |
| 同步 | `SYNC_REQ/START/END` | 0x02-04 | 参数同步握手 |
| 效果 | `DRC` | 0x10 | DRC 动态范围控制参数 |
| 效果 | `REVERB` | 0x11 | 混响参数 |
| 效果 | `EQ` | 0x12 | 均衡器参数 |
| 效果 | `DELAY` | 0x13 | 延迟参数 |
| 效果 | `GAIN` | 0x14 | 增益参数 |
| Looper | `LOOPER` | 0x20 | Looper 控制命令 |
| Looper | `LOOPER_SEG_STATE` | 0x21 | 段状态同步 |
| 控制 | `VOLUME` | 0x30 | 音量控制 |
| 控制 | `METRONOME` | 0x31 | 节拍器设置 |
| 控制 | `SYSTEM` | 0x32 | 系统命令 |
| 控制 | `BATTERY_CALIB` | 0x33 | 电池校准 |
| 数据 | `WAV_EXPORT` | 0x40 | WAV 文件导出下载 |

**关键 API**：

```c
void BleProto_Init(void);                                   // 初始化协议引擎
void BleProto_Process(void);                                // 周期处理（ACK超时等）
void BleProto_SendReliable(uint8_t cmd, uint8_t *data, uint16_t len);  // 可靠发送
void BleProto_SendOnce(uint8_t cmd, uint8_t *data, uint16_t len);      // 单次发送
void BleProto_RegisterDataHandler(BleProtoDataHandler_t handler);      // 注册回调
```

### 3.2.4 Shell over BLE (`shell_io_ble`)

将 BLE 数据通道桥接到 Shell 命令系统，实现手机 App 遥控：

```c
// 当 BLE 收到数据时，注入 Shell 解析器
void ShellIO_BLE_OnDataReceived(uint8_t *data, uint16_t len);
```

### 3.2.5 SBC 解码器 (`sbc_codec`)

蓝牙 A2DP 必需的 SBC 音频编解码器：
- **输入**：蓝牙 A2DP SBC 编码帧
- **输出**：PCM 音频数据，通过 `BT_ReadAudioData()` 送入 Effect Graph

## 3.5 电源管理 (power_mgr/)

**文件**：`power_mgr/battery_drv.h/.c`、`battery_calib.h/.c`

### 功能

1. **电池电压采集**：通过 ADC 通道周期采样
2. **电量计算**：电压 → 百分比映射
3. **电池校准**：用户可进行多点校准，提高精度
4. **低电量告警**：通过事件系统发布 `EVT_SYS_BATTERY_LOW`

### 校准流程

```
1. 连接稳压电源到电池接口
2. 设置多个电压点（如 4.2V, 3.8V, 3.5V, 3.2V）
3. 每个点记录 ADC 读取值
4. 数据存入 Flash，用于线性插值
```

### Shell 命令

```bash
battery              # 查看电池状态
battery_calib        # 进入校准模式
```

## 3.6 提示音播放 (remind_sound/)

**文件**：`remind_sound/remind_sound.h/.c`

### 功能

播放嵌入式 **const 数组**中的音频数据（MP3/WAV），用于开机/关机提示音、事件音效等。

### 架构设计

```
┌─────────────────────────────────────────┐
│          RemindSound_Play()              │
│  ┌─────────────────────────────────┐    │
│  │  1. 设置 g_remind_sound_active  │    │  → 暂停 Effect Graph DAC 输出
│  │  2. malloc 19KB 解码缓冲区      │    │
│  │  3. mv_mopen() 绑定数据源       │    │  → 从 const 数组按需读取
│  │  4. 自动检测 MP3/WAV 格式        │    │
│  │  5. audio_decoder_initialize()  │    │
│  │  6. while (有数据) {            │    │
│  │       解码 → 写 DAC FIFO        │    │
│  │     }                           │    │
│  │  7. free 解码缓冲区             │    │
│  │  8. 恢复 g_remind_sound_active  │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

### 关键 API

```c
// 从已注册表中按名称播放
int RemindSound_PlayByName(const char *name);   // 例: "on", "off"

// 从已注册表中按索引播放
int RemindSound_PlayByIndex(uint8_t id);        // 例: 0=开机音, 1=关机音

// 直接播放原始数据（底层 API）
void RemindSound_Play(const uint8_t *data, uint32_t size, uint8_t vol_pct);

// 列出所有注册的提示音
void RemindSound_ListAll(void);
```

### 重要：堆空间约束

> ⚠️ 提示音播放需要临时分配 **19KB** 堆内存。开机提示音必须在 `InitAudioEffects()` 之前播放（此时堆约 77KB），初始化效果器后堆仅剩 ~11KB，不够分配。

## 3.8 USB 设备驱动 (USB/)

**文件**：`USB/` 目录

### 功能

USB 2.0 OTG 设备模式驱动，支持：
1. **USB Audio Class 1.0**：双向 48kHz/16bit 立体声，PC 端声卡
2. **USB CDC-ACM**：虚拟串口，Shell 命令行
3. **USB CDC-ECM** (可选)：网络接口
4. **USB MSC** (可选)：大容量存储，固件升级

### USB 复合设备

```
┌──────────── USB Device ─────────────┐
│                                     │
│  ┌─────────┐  ┌─────────┐          │
│  │ Audio   │  │ CDC-ACM │          │
│  │(Speaker+│  │(虚拟串口)│          │
│  │  Mic)   │  │         │          │
│  └─────────┘  └─────────┘          │
│                                     │
│  USB Audio 数据 → Effect Graph     │
│  USB CDC 数据 → Shell 命令系统      │
└─────────────────────────────────────┘
```
