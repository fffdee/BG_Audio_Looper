> **本章目标**：理解从上电到应用运行的完整启动序列，掌握诊断和调试方法
> **对应代码**：`bootloader/`、`MVsB1_Base_SDK/startup/`、`BanBox/src/main.c`

## 8.1 Flash 布局

### 分区表

```
Flash 地址          大小      分区         内容
──────────────────────────────────────────────────
0x00000000         256 KB    Bootloader   启动引导程序
0x00040000         2 MB      Partition A  主应用固件
0x00240000         2 MB      Partition B  备份应用固件
0x00440000         4 KB      分区标志区    PartFlag_t 结构体
```

### 分区标志结构

```c
typedef struct {
    uint8_t  active_part;        // 当前激活分区 (0=A, 1=B)
    uint8_t  boot_fail_cnt;      // 启动失败计数
    uint32_t magic;              // 幻数校验
} PartFlag_t;
```

**看门狗回退机制**：
- 每次 Bootloader 启动 APP 时，`boot_fail_cnt++`
- APP 成功运行后，调用 `Boot_ConfirmSuccess()` 重置 `boot_fail_cnt=0`
- 若 APP 连续失败 (看门狗复位)，`boot_fail_cnt` 超过阈值 → 自动切换到备份分区

## 8.2 完整启动序列

### 阶段 0：硬件上电 (CPU 底层)

```
电源上电 → CPU Reset
    │
    ▼
Reset Vector (0x00000000)
    │  PC = 0x00000000 → 执行 crt0.S 第一条指令
    ▼
exception_vector (异常向量表)
    │  共 9 个硬件异常入口
    ▼
_start → j ___start
```

### 阶段 1：汇编级启动 (`crt0.S` - `___start`)

```
___start:
    ├── nds32_init 宏
    │   ├── 设置 GP (Global Pointer) 全局指针
    │   ├── 设置 SP (Stack Pointer) 栈指针 = _stack (0x20004000)
    │   └── 设置 FP (Frame Pointer) 帧指针
    ├── 清零 $misc_ctl 寄存器 (关闭 BTB 分支预测)
    └── bal __init  # 跳转 C 语言初始化
```

### 阶段 2：C 运行时初始化 (`init-default.c` - `__init()`)

```
__init():
    │
    ├── __cpu_init()
    │   ├── 配置 MMU_CTL (位 0x800000)
    │   ├── INT_MASK = 0              # 关闭所有中断
    │   ├── 设置 IVB = __executable_start  # 中断向量基址
    │   ├── 配置 PSW (INTL=0, CPL=7)
    │   ├── 配置可编程中断优先级
    │   ├── 使能 FPU (如果支持)
    │   └── 清除所有 pending 中断
    │
    ├── __c_init()
    │   ├── [Bootloader]: 复制 .data 段 (Flash LMA → SRAM VMA)
    │   ├── [Bootloader]: 清零 .bss 段
    │   ├── [APP]: 检查 BOOT_HANDOFF_MAGIC (0xDEADBEEF @ 0x20000000)
    │   │   ├── Magic 存在 → 跳过 .data/.bss 初始化 (由 Bootloader 完成)
    │   │   └── Magic 不存在 → 自行执行 .data/.bss 初始化
    │   └── 注意：APP 跳过 .data 复制是为了避免 SBus/IBus 总线冲突
    │
    ├── HardwareStackProtectEnable()
    │   └── SP_BOUND = 0x20003000    # 栈溢出保护边界
    │
    ├── Chip_MemInit()               # 芯片内存子系统 + MPU 配置
    │
    └── [APP only]: DbgUartInit()    # 重新初始化 UART 驱动状态
        └── 因为 .bss 清零了 Bootloader 的设置
            
    # 返回 crt0.S
    bal main   # 跳转 C main()
```

### 阶段 3A：Bootloader main()

```
main() @ bootloader/src/main.c:
    │
    ├── Chip_Init(1)                 # 芯片级初始化
    ├── WDG_Disable()                # 关闭看门狗
    ├── 时钟配置
    │   ├── 使能所有模块时钟
    │   ├── 配置 PLL → 288MHz
    │   ├── 配置 APLL → 240MHz
    │   └── 选择系统时钟源
    ├── UART 初始化 (GPIO A9/A10 → UART1, 115200 8N1)
    ├── USB 时钟 (4 分频, APLL 源)
    ├── Remap TCM → Remap_InitTcm(0, 12)
    ├── SPI Flash Init → 80MHz, 4-bit QSPI, XIP 模式
    ├── DMA 通道分配
    ├── GIE_ENABLE()                 # 使能全局中断
    ├── Timer2 启动 (1ms 周期)
    ├── 打印 Banner: "BG_CARD SDK"
    │
    ├── Boot_CheckAndJumpIfNeeded()
    │   ├── 读取 PartFlag_t @ 0x4400000
    │   ├── 选择 active_part → Partition A (0x040000) 或 B (0x240000)
    │   ├── boot_fail_cnt++
    │   ├── 复制 APP 的 .data 段到 SRAM
    │   ├── 设置 BOOT_HANDOFF_MAGIC (0xDEADBEEF @ 0x20000000)
    │   └── Boot_JumpTo(addr) ──→ 直接跳转 APP 入口 (永不返回)
    │
    └── [如果 Boot_CheckAndJumpIfNeeded 返回 - 升级模式]
        ├── prvInitialiseHeap()
        ├── 使能 SWI 中断
        ├── xTaskCreate(UpdataTask)   # 创建 USB 固件升级任务
        └── vTaskStartScheduler()     # 启动 FreeRTOS
```

### 阶段 3B：BanBox APP main()

```
main() @ BanBox/src/main.c:
    │
    ├── diag_putc('M')              # 早期诊断字符
    ├── WDG_Disable()
    ├── DbgUartInit(1, 115200, 8, 0, 1)  # 重新初始化 UART 状态
    ├── SPI Flash & DMA 驱动状态重新初始化 (因为 .bss 清零)
    ├── 打印 "[APP] main() entered (from bootloader)"
    ├── Boot_CheckAndJump()         # 仅确认当前分区
    ├── GIE_ENABLE()
    ├── Timer2 启动 (1ms)
    ├── prvInitialiseHeap()         # FreeRTOS 堆 72KB
    ├── 使能 SWI 中断
    ├── SarADC_Init()               # SAR ADC 初始化
    ├── 创建 FreeRTOS 队列
    ├── spi_init()                  # SPI 硬件初始化
    │
    ├── DrvFramework_FullInit()     # ★ 驱动框架全量初始化 (详见第4章)
    │
    ├── EffectGraph VFS 挂载
    ├── ShellCmdAudioVfs 初始化
    │
    ├── xTaskCreate(MainTask, "Main", 4096, NULL, 5, NULL)
    └── vTaskStartScheduler()       # FreeRTOS 调度器启动
```

### 阶段 4：MainTask 应用任务

```
MainTask() @ BanBox/src/main.c:
    │
    ├── Boot_ConfirmSuccess()       # 重置 boot_fail_cnt = 0
    │
    ├── BG_AudioManager.Audio_Init()  # ★ 音频系统初始化 (详见第6章)
    │
    ├── 升级引擎初始化
    │   ├── App_Upgrade_Init()
    │   └── CDC_Upgrade_Init()
    │
    └── 主循环 (forever):
        ├── BLE 同步响应检查
        ├── CDC 文件管理器
        ├── CDC 固件升级处理
        ├── BG_AudioManager.Audio_Loop()   # ★ 音频主循环
        ├── BG_UI.Update(20)               # UI 刷新
        └── hardware_check()               # 硬件状态检查
```

## 8.3 诊断字符序列

APP 启动时会通过 UART1 MMIO 输出一串诊断字符，用于精确定位启动失败位置：

```
c → h → r → A → B → y → z → ! → D → E → S → M → 1 → U → R
→ 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9 → a → b → c
```

| 字符 | 含义 |
|------|------|
| `c` | `__c_init` 开始 |
| `h` | `.data` 复制完成 |
| `r` | `.bss` 清零完成 |
| `A` | 进入 APP main 早期 |
| `B` | SPI Flash 初始化 |
| `y` | PLL 配置 |
| `z` | 系统时钟配置 |
| `!` | 异常/错误 |
| `D` | 驱动初始化 |
| `E` | Effect Graph 初始化 |
| `S` | 调度器启动 |
| `M` | `main()` 已进入 |

## 8.4 交接协议 (Bootloader → APP)

### 协议细节

```
Bootloader 在跳转前:
  [0x20000000] = 0xDEADBEEF   (BOOT_HANDOFF_MAGIC)
  [0x20000004] = 启动原因
  [0x20000008] = 当前运行分区
  [0x2000000C] = APP 入口地址

APP 在 __c_init() 中检测:
  if (*(uint32_t*)0x20000000 == 0xDEADBEEF) {
      // Bootloader 已帮我做了 .data/.bss 初始化
      // 跳过 MEMCPY/MEMSET，避免总线冲突
      return;
  }
```

### 为什么需要 Magic？

- Andes NDS32 CPU 的 SBus (系统总线) 和 IBus (指令总线) 可能竞争
- 如果 APP 在 XIP 模式下重新执行 Flash 读取 + SRAM 写入，可能与 Bootloader 正在执行的指令产生总线冲突
- 通过 Magic 标志让 Bootloader 代劳 .data 复制，APP 不再重复操作

## 8.5 分区升级 (A/B Update)

### 升级流程

```
正常启动:
  Bootloader → 读 PartFlag → 选择 active_part → 跳转 APP

升级流程:
  1. APP 接收新固件 (USB CDC/蓝牙/BLE)
  2. 写入 inactive_part (另一个分区)
  3. 更新 PartFlag: active_part = inactive_part
  4. 触发系统复位
  5. Bootloader 读到新的 active_part → 启动新版固件

看门狗回退:
  1. 新版固件连续启动失败 (看门狗复位)
  2. boot_fail_cnt > 阈值 (如 5 次)
  3. Bootloader 自动切回旧分区
```
